## Problem Statement

El proyecto tiene trabajo significativo hecho en sesiones anteriores de Claude Code que no está documentado ni commiteado. Para publicarlo como open source se necesita:
1. Un CHANGELOG que documente qué se hizo vs. el upstream base
2. Un TODO claro de qué queda pendiente
3. Sincronizar CLAUDE.md con la realidad (Fase 4 hecha pero marcada como pendiente)

## What Makes This Cool

Este proyecto resuelve algo que los MCP servers de recetas actuales no hacen: convierte cualquier receta (URL, texto, foto) aplicando las reglas reales del formato Thermomix y la sube directamente a tu cuenta de Cookidoo sin intervención manual. El `@mcp.prompt()` que lo expone como `/receta` en Claude Desktop y Claude Code a la vez es un approach elegante que evita la limitación de `~/.claude/commands/`.

## Premises

1. El trabajo del working tree (refactor, tests, setup.sh, MCP prompt) fue hecho en sesiones previas y es el estado real del proyecto.
2. La Fase 4 (MCP Prompt /receta) está HECHA en server.py — solo falta actualizar el checkbox en CLAUDE.md.
3. Los archivos sin commitear necesitan un commit antes de publicar.

## Approaches Considered

### Approach A: Solo CHANGELOG.md separado
- Archivo nuevo, formato estándar
- Effort: S | Risk: Low
- Pros: clean, searchable
- Cons: CLAUDE.md sigue desincronizado

### Approach B: Solo README update
- Effort: S | Risk: Low
- Pros: todo en un lugar
- Cons: README se vuelve largo, mezcla docs con estado

### Approach C: CLAUDE.md actualizado + CHANGELOG.md nuevo (elegido)
- Effort: S | Risk: Low
- Pros: CLAUDE.md honesto, CHANGELOG open source, TODO estructurado
- Cons: dos archivos a mantener

## Recommended Approach

**Approach C.** CLAUDE.md queda como fuente de verdad del plan, CHANGELOG.md como log público del progreso.

### v0.2.0 — thermomix-mcp (En desarrollo, no publicado)

_Construido sobre `alexandrepa/mcp-cookidoo` como base_

#### Fase 1 — Setup del fork
- Cambio de dependencia: `miaucl/cookidoo-api` → `Mariosd23/cookidoo-api` (fork con PR #179)
  - El fork añade `create_custom_recipe` y `edit_custom_recipe` que el paquete oficial no tiene
- Suite de tests añadida: 43 tests unitarios (`test_cookidoo_service.py`, `test_schemas.py`, `test_server.py`)
- Infraestructura de test: `pytest.ini`, `tests/conftest.py`

#### Fase 2 — Refactor de `cookidoo_service.py`
- **Bug fix:** Eliminado `time.sleep(5)` en contexto async — bloqueaba el event loop completo
- **Bug fix:** Eliminado acceso a `self._api_client._session` (atributo privado, frágil ante actualizaciones de la librería)
- **Refactor:** 50+ líneas de llamadas HTTP manuales (POST + sleep + PATCH) reemplazadas por `CookidooCreateCustomRecipe` del fork Mariosd23 (~5 líneas)
- **Feature:** `edit_custom_recipe` añadido (disponible gratis con el fork)
- **Fix:** Tipo de retorno corregido de `str` a `CookidooCustomRecipe`

#### Fase 3 — Configuración flexible
- `load_cookidoo_credentials()` ahora retorna 5 valores: `(email, password, country, language, device)`
- Añadidas variables a `.env.example`: `COOKIDOO_COUNTRY`, `COOKIDOO_LANGUAGE`, `COOKIDOO_DEVICE`
- `CookidooService.__init__` acepta `country`, `language`, `device` con defaults `es`, `es-ES`, `TM6`
- Locale ya no hardcodeado a `fr-FR` — configurable desde `.env`
- Dispositivo ya no hardcodeado a `TM6` — configurable desde `.env`
- Soporte para TM5, TM6, TM7, TM31 (los límites de temperatura se definieron en Fase 4)

#### Fase 4 — MCP Prompt `/receta`
- `@mcp.prompt() def receta()` añadido en `server.py` — expone el skill en Claude Desktop y Claude Code simultáneamente
- Reglas de conversión embebidas (es-ES):
  - **Regla 1:** Separación obligatoria de paso-ingredientes vs. paso-acción de máquina
  - **Regla 2:** Cualquier instrucción con `seg/vel`, `min/vel`, `°C`, `Varoma` → paso propio
  - **Regla 3:** Usar cantidades exactas de la lista de ingredientes en los pasos
- Vocabulario Thermomix es-ES: `seg`, `min`, `vel`, `giro inverso`, `Varoma`, `modo amasar 🌾`
- Tabla de operaciones de referencia (trocear, mezclar, sofreír, cocer, Varoma, amasar)
- Flujo de 5 pasos: conectar → convertir → validar → confirmar → subir
- Límites de temperatura por dispositivo: TM31 100°C, TM5 120°C, TM6 160°C, TM7 180°C
- README.md completamente reescrito con instalación, setup, configuración
- `setup.sh` añadido: instalación con un comando (uv sync + gstack + bun + .env)
